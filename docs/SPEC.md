# Спецификация плейбла «Спаси котика» (Stack Ball)

Неофициальный концепт для собеседования. Stack Ball — игра Azur Games.

## Сценарий (20–30 секунд)
| Время | Что происходит | Зачем |
|---|---|---|
| 0–1,8 с | Камера внизу: котик в клетке плачет, над ним «HELP!». Сверху надпись «SAVE THE KITTY!». Камера взлетает к шару | Эмоция и цель в первые секунды |
| до касания | Затемнение, анимированная рука, «HOLD TO SMASH». Шипы и таймер стоят | Подсказка из кейса Playworks; требование AppLovin «таймер после первого касания» |
| 2–15 с | Держишь — шар пробивает кольца (куски и кубики летят), отпускаешь — шар прыгает. Первые 5 колец без чёрных. Сверху опускаются шипы. Полоса прогресса ведёт к значку котика | Удовольствие от разрушения + давление |
| во время игры | 12 колец подряд — режим огня: шар оранжевый и неуязвим. Шипы близко — красная виньетка по краям и писк | Яркий момент и напряжение |
| победа | Шар падает на платформу, клетка разлетается, котик прыгает, сердечки и конфетти, «KITTY SAVED!» | Награда |
| проигрыш | Чёрный сектор или шипы — шар разлетается, «SO CLOSE! 72%», кнопка «TRY AGAIN». Вторая неудача — сразу end card | «Почти получилось» мотивирует установить |
| end card | Иконка, «Stack Ball», кнопка «PLAY NOW» (пульсирует), «Replay» мелко. Нажатие в любом месте карточки — в магазин | Конверсия в установку |
| страховка | Через 40 с после первого касания end card показывается в любом случае. Без касаний 4 с — подсказка возвращается | Требования сетей и UX |

## Управление и баланс (стартовые значения, `game/src/main.js`, блок Settings)
Кольцо из 8 секторов, расстояние между кольцами 0,42. Скорость пробивания 4,4 ед/с (≈10 колец/с). Отскок 7,6 ед/с, гравитация −32, скорость свободного падения не больше 12 ед/с. Режим огня после 12 колец подряд, 1,5 с: чёрное не страшно, но пробивать можно только пока держишь палец (как в оригинале; раньше огонь пробивал сам и уровень проходился за секунду). Колец в «Спасении» — 30, в «Классике» — 26 на уровень, 2 уровня. Чёрные сектора с 6-го кольца, на 62% колец, по 2–3 сектора подряд. Башня строится из зерна (seed), поэтому у каждой попытки она одинаковая и честная.

Шипы: старт на 4,4 выше первого кольца, скорость 0,8 ед/с. Если игрок ушёл вперёд больше чем на 3,8, шипы догоняют быстрее, чтобы всегда оставаться в кадре (напряжение без лишней сложности). Во второй попытке шипы на 20% медленнее. Красная виньетка — когда до шипов меньше 2,2, писк — меньше 1,4.

Проверено ботом на этапе 2 (держит палец долю времени): 60% — спас за 7 с, 45% — за 12 с, 33% — за 15 с, 25% — «So close!» на 83% (шипы), 15–20% — проигрыш на 37–43%. То есть средний игрок спасает котика за 7–15 секунд, медленный получает «почти получилось».

## Варианты (параметр `?variant=`)
`rescue` — основной (B). `classic` — контроль (A): без котика и шипов, два уровня. `pick` — третий (C): всё как в B плюс выбор шара после интро. Отличие от B ровно одно, чтобы тест был чистым.

Шары в C: метеорит — крупнее разлёт кубиков и тряска камеры; ракета — пробивает на 30% быстрее; огненный — режим огня уже после 8 колец. Выбор шара считается первым касанием (событие `ball_pick`).

Флаг `?demo=1` («смотри, потом играй») работает с любым вариантом: после интро 3 секунды игра играет сама в ритме «держит полсекунды, отпускает полсекунды», внизу рука-призрак и «WATCH», чёрные сектора обходит, проиграть не может, режим огня в показе не включается. Потом «YOUR TURN!» и подсказка. Касание во время показа сразу отдаёт управление игроку. Событие `demo_done` (`skipped`, `rings`).

Проверено ботом на этапе 3: все шары проходятся за 4–15 с (огненный быстрее всех — это его свойство); вариант B без показа — как на этапе 2.

Язык: `?lang=en` (по умолчанию, реклама для мировых рынков) или `?lang=ru`.

## Требования сетей (что соблюдаем)
| Требование | Как сделано |
|---|---|
| Один HTML, без внешних запросов | Сборка Vite + vite-plugin-singlefile, three.js из npm внутри файла, шрифты системные (Google Fonts нельзя) |
| Размер до 5 МБ (Meta — HTML до 2 МБ) | Цель до 2 МБ, проверка `npm run check` |
| Звук только после касания | AudioContext создаётся по первому касанию, звуки синтезируются WebAudio, без файлов |
| Таймер после первого касания | Шипы и страховочный таймер стартуют по первому касанию |
| Нельзя в магазин с первого касания | CTA только на end card и кнопке |
| Кнопка в магазин | `game/src/ad.js`: `mraid.open()` → `FbPlayableAd.onCTAClick()` → `ExitApi.exit()` → `window.open()` |
| Вертикаль и горизонталь | Камера и интерфейс подстраиваются под пропорции экрана |
| MRAID: старт по готовности | Если есть `mraid`, ждём `ready` и видимости |

Отдельные сборки под каждую сеть (MRAID-обёртка, ZIP с ExitApi для Google, проверка в их инструментах) — этап 4.

## События аналитики (`game/src/analytics.js`)
Каждое событие: `{ name, t }`, где `t` — миллисекунды с загрузки. Личных данных нет.

| Событие | Что значит |
|---|---|
| `loaded` | Плейбл загрузился, от него считается воронка |
| `intro_done` | Камера долетела до шара |
| `first_touch` (+ `sinceLoad`) | Начал играть (engagement), время до касания |
| `rings_10` | Пробил 10 колец |
| `fire_mode` | Дошёл до режима огня |
| `fail` (+ `reason`: `black` или `spikes`, `progress`) | Проиграл, где и на скольких процентах |
| `retry` | Нажал «Try again» |
| `win` | Спас котика |
| `endcard_shown` (+ `reason`: `win`, `fails`, `timeout`) | Дошёл до end card |
| `cta_click` (+ `where`: `button` или `card`) | Нажал в магазин (CTR) |
| `replay` | Переиграл с end card |
| `ball_pick` (+ `ball`) | Выбрал шар (вариант C) |
| `demo_done` (+ `skipped`, `rings`) | Показ закончился сам или игрок перебил его касанием |

Куда уходят: массив `window.__pbEvents`, `console.debug`, `postMessage` родителю (для демо-страницы с воронкой на этапе 4) и счётчики в `localStorage` (в try/catch).

## Безопасность (по `security-base`)
Нет сервера, ключей, форм и личных данных. Ссылки на магазины — константы в коде. Нет `eval` и `innerHTML` (тексты через `textContent`, сердечки собираются DOM-методами). `postMessage` отправляет только имена событий. Перед публикацией демо-страницы (этап 4) — `security-base/checklists/before-release.md` и Gitleaks.

`npm audit` (26.10.2026) показывает уязвимости esbuild/Vite. Они касаются только локального сервера разработки (`npm run dev`), который слушает лишь 127.0.0.1; в собранный `dist/index.html` эти пакеты не попадают. Vite закреплён на 5.4.21 (последняя версия ветки 5).

## Проверка без видимого браузера
`window.__sim(секунды, держать)` прогоняет игру по 1/60 с; `window.__danger()` — опасен ли сектор под шаром; `window.__intro()` — перезапуск с интро; `window.__pause = true` — остановить обычный цикл. Только для проверки.
