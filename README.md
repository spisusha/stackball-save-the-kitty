# Stack Ball: Спаси котика — playable-реклама, сделанная с Claude Code

**Играть:** https://spisusha.github.io/stackball-save-the-kitty/play/
**Варианты для A/B-теста и живая воронка:** https://spisusha.github.io/stackball-save-the-kitty/demo/
**Research:** https://spisusha.github.io/stackball-save-the-kitty/research/

Неофициальный концепт playable-рекламы для игры Stack Ball (Azur Games), сделанный к собеседованию на позицию AI Game Designer. Это не реклама Azur Games; Stack Ball и все права на игру принадлежат Azur Games.

*English summary: an unofficial playable ad concept for Azur Games' Stack Ball, built with Claude Code. Hold to smash through the tower, save the kitty before the spikes come down. One self-contained HTML file (~0.5 MB, no external requests), MRAID / Meta / Google CTA, A/B variants and funnel events.*

## Что это
Механика Stack Ball (держи палец — шар пробивает кольца, отпусти перед чёрным сектором) плюс крючок, которого нет в текущей рекламе игры: внизу котик в клетке, сверху опускаются шипы. Успел пробиться вниз — котик спасён, дальше экран с кнопкой в магазин. Проиграл — «So close! 83%» и одна попытка ещё.

## Как я работал
Процесс построен так, как работал бы человек в отделе плейблов: от анализа рынка к гипотезе, от гипотезы к плейблу и вариантам для теста.

**Research.** Разобрал активную рекламу Azur в Meta Ad Library (около 330 объявлений; Stack Ball — 5 из 26 самых показываемых, запуск 28.09.2026) и конкурента Helix Jump (его лучшие объявления крутятся почти год — признак окупаемого креатива). Нашёл кейс ironSource: первый плейбл Stack Ball проигрывал видео и выиграл только после доработки подсказок. Собрал требования сетей и метрики (IPM, CTR, доля начавших, доля дошедших до конца, удержание D1). Подробно — [research](https://spisusha.github.io/stackball-save-the-kitty/research/) и `docs/RESEARCH.md`.

**Выбор игры и гипотеза.** Stack Ball: живой хит Azur, механика в одно касание укладывается в 25 секунд. Гипотеза: эмоция и давление («спаси котика, пока опускаются шипы») поднимут IPM по сравнению с чистым геймплеем. Почему не копия: тот же геймплей, но новый крючок, который можно проверить в тесте (`docs/DECISIONS.md`).

**Плейбл.** Интро с котиком крупным планом, подсказка «держи», игра, режим огня, победа или проигрыш «почти получилось», end card с кнопкой в магазин. Баланс проверен автоматическим ботом за игроков разной скорости: средний игрок спасает котика за 7–15 секунд, медленный получает «так близко».

**Варианты для A/B-теста.** В каждом меняется одна вещь, чтобы было понятно, что сработало:

| Вариант | Что меняется | Гипотеза |
|---|---|---|
| A. Классика | Только механика | Контроль |
| B. Спаси котика | + котик и шипы | Эмоция и давление поднимут IPM |
| C. Выбери шар | B + выбор: метеорит (бьёт 2 кольца), ракета (в 1,7 раза быстрее), огненный (огонь через 6 колец) | Выбор в первые секунды увеличит долю начавших играть |
| + Показ | Первые 3 секунды игра играет сама, потом «Теперь ты!» | Меньше людей растеряется на старте |

**Метрики.** Плейбл отправляет события воронки: загрузка, первое касание (и время до него), 10 колец, режим огня, проигрыш (где и на скольких процентах), повтор, победа, показ end card, клик «Играть». На странице вариантов они видны в реальном времени (`docs/SPEC.md`).

**Чем сделано.** Весь код написан с Claude Code. Three.js — 3D, всё собрано из простых фигур в коде (без моделей и Blender). Звуки синтезированы в браузере (WebAudio), файлов нет. Vite + vite-plugin-singlefile собирают всё в один HTML.

## Требования рекламных сетей
| Требование | Как сделано |
|---|---|
| Один файл, без внешних запросов | Всё внутри `dist/index.html`, ~0,5 МБ (лимиты сетей 2–5 МБ), проверка `npm run check` |
| Кнопка в магазин | MRAID `mraid.open()` (AppLovin, Unity, Mintegral и др.), Meta `FbPlayableAd.onCTAClick()`, Google `ExitApi.exit()`, иначе обычная ссылка |
| Звук и таймер | Звук только после первого касания, шипы и 40-секундная страховка стартуют после касания |
| В магазин не с первого касания | Кнопка только на end card |
| Вертикаль и горизонталь | Камера и интерфейс подстраиваются |

## Как запустить на компьютере
Нужны [Node.js](https://nodejs.org) 18+ и Git.
```
git clone https://github.com/spisusha/stackball-save-the-kitty.git
cd stackball-save-the-kitty
npm install
npm run dev
```
Откройте http://127.0.0.1:5174/game/ — это режим разработки, изменения в коде видны сразу. На компьютере удобно включить режим телефона в инструментах разработчика браузера (F12, значок телефона). Управление мышью: зажать кнопку мыши — пробивать, отпустить — шар прыгает.

Параметры в адресе: `?lang=ru` — русский, `?variant=classic` — без котика, `?variant=pick` — выбор шара, `?demo=1` — сначала игра показывает, как играть. Их можно сочетать: `?variant=pick&demo=1&lang=ru`.

Собрать итоговый файл:
```
npm run build    # dist/index.html — плейбл одним файлом, открывается двойным щелчком без интернета
npm run check    # проверка размера и отсутствия внешних запросов
npm run site     # _site/ — сайт для GitHub Pages: главная, /play/, /demo/, /research/
```
Посмотреть на телефоне в той же Wi-Fi сети: `python -m http.server 8080 --bind 0.0.0.0 --directory dist`, затем на телефоне `http://<адрес компьютера>:8080/` (игра) и `/demo/` (варианты).

Сайт публикуется сам: каждый пуш в `main` запускает GitHub Actions (`.github/workflows/pages.yml`), который собирает и выкладывает `_site/` на GitHub Pages.
